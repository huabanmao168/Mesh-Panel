# 第 2 块：装机

## 目标

在第 1 块"主控能 SSH 连上节点"的基础上，加一个"**部署**"按钮，点一下主控就帮你把节点初始化好：

1. 检测节点系统（架构 / 发行版）
2. 下载 sing-box 二进制（**固定版本**，下面有讲为啥）
3. 写一个最小可启动的 sing-box 配置（占位，不开任何入站）
4. 装 systemd unit，开机自启
5. 装一个临时探针脚本（**第 2 块还没真正的 Go agent**，先用 shell 脚本占位，第 3 块再换）
6. 启动服务，回报版本号和运行状态

跑完节点详情页能看到："sing-box v1.x.x 已安装，运行中"。

---

## 怎么对抗 sing-box 爱乱改的毛病

这是这块**最重要的设计决策**，单独拎出来讲。

### 痛点

- sing-box 在 1.8 → 1.9 → 1.10 这条路上多次改字段名（`inbounds[].sniff` → `sniff` 移到 inbound 顶层、`experimental.clash_api.store_selected` 等开关挪位置、`tun` / `dns` 模块多次重构）
- 升级一次 = 旧配置 JSON 全报错 = 所有节点 reload 失败 = 你深夜被叫起来救火

### 对策（四条防线）

**① 锁版本，不要追最新**
- 主控数据库里存**全局默认 sing-box 版本号**，比如 `1.10.7`，所有新装节点都用这个。
- 每个节点再存自己的**实际版本号**（装上去那一刻记下来）。
- "升级 sing-box"是一个**显式动作**（前端有按钮，要点），永远不自动升级。

**② 版本绑配置 schema**
- 配置生成器（第 4 块写）按 sing-box 版本走分支：`generate_config(version, params)`。
- 内部维护一张"版本 → schema 适配器"映射表。1.10 一套、1.11 一套，互不干扰。
- 升级 sing-box 时主控**重新生成**该节点的配置再推，绝不直接复用旧 JSON。

**③ 配置 schema 版本号入库**
- 节点表加一列 `config_schema`（比如 `"singbox-1.10"`），记这套配置是按哪个版本生成的。
- 升级时对比 `wanted_version` vs `config_schema`，不一致就重新生成。

**④ 升级前 dry-run**
- sing-box 有 `sing-box check -c config.json` 子命令，能离线校验配置合法性。
- 任何 reload 之前先 `check`，不通过就不重启服务，保留旧配置继续跑。

**第 2 块本块要落地的部分**：① 版本锁定 + 版本号入库 + `sing-box check` 校验。② ③ 留给第 4 块（那时才真开始生成业务配置）。

## 装哪个版本

**默认值**：`1.10.7`（截至当前的最后一个 1.10.x 稳定版，1.11 还在频繁改）。

- 在 `backend/config.py` 加常量 `DEFAULT_SINGBOX_VERSION = "1.10.7"`
- 同时存到一张新表 `settings`（key/value 全局设置），前端"全局设置"页可以改（这页本块不做 UI，先用 API）
- 下载地址：`https://github.com/SagerNet/sing-box/releases/download/v{ver}/sing-box-{ver}-linux-{arch}.tar.gz`

架构检测：

```bash
case "$(uname -m)" in
  x86_64)  ARCH=amd64 ;;
  aarch64) ARCH=arm64 ;;
  armv7l)  ARCH=armv7 ;;
  *) echo "unsupported arch"; exit 1 ;;
esac
```

## 节点上的最终布局

```
/opt/mesh-panel/
├── sing-box                # 二进制
├── version                 # 纯文本，存版本号，方便升级检测
├── agent.sh                # 临时探针（第 3 块换成 Go）
└── README                  # 说明这台机是被 mesh-panel 接管的

/etc/sing-box/
└── config.json             # 主控推下来的配置（本块只放占位）

/etc/systemd/system/
├── sing-box.service        # 跑 sing-box
└── socks-agent.service     # 跑 agent.sh（本块）→ Go agent（第 3 块）
```

**为啥不放 /usr/local/bin**：项目自包含一个目录，卸载 `rm -rf /opt/mesh-panel` 干净利落。

## install.sh 干的活（按顺序）

1. 检查 root 权限
2. 检测架构（amd64 / arm64 / armv7）
3. 创建 `/opt/mesh-panel/` 和 `/etc/sing-box/`
4. 下载 sing-box tar.gz → 解压 → 移到 `/opt/mesh-panel/sing-box`
5. 写版本号到 `/opt/mesh-panel/version`
6. 写**占位配置** `/etc/sing-box/config.json`（log only，无 inbound，启动不报错即可）
7. 写两个 systemd unit
8. `systemctl daemon-reload && systemctl enable --now sing-box.service`
9. **本块先不启动 socks-agent.service**（agent.sh 只是个 placeholder，第 3 块再说）
10. 打印 JSON 结果到 stdout：`{"ok":true,"version":"1.10.7","singbox_status":"active"}`

主控解析这个 JSON 收尾，写回 nodes 表。

## 占位配置长啥样

```json
{
  "log": { "level": "info", "timestamp": true },
  "inbounds": [],
  "outbounds": [
    { "type": "direct", "tag": "direct" }
  ]
}
```

足够让 sing-box 进程跑起来不退出，等第 4 块往里填东西。

## systemd unit

**`/etc/systemd/system/sing-box.service`**：

```ini
[Unit]
Description=sing-box (managed by mesh-panel)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStartPre=/opt/mesh-panel/sing-box check -c /etc/sing-box/config.json
ExecStart=/opt/mesh-panel/sing-box run -c /etc/sing-box/config.json
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=3
LimitNOFILE=1048576

[Install]
WantedBy=multi-user.target
```

注意 `ExecStartPre=... check` —— 配置烂掉的话进程压根起不来，避免被 Restart=on-failure 无限循环烧 CPU。

## API 新增

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/settings` | 读全局设置（默认版本号等） |
| PATCH | `/api/settings` | 改全局设置 |

## 后端怎么实现

### `backend/deploy/installer.py`（新增模块）

```python
def deploy_node(node) -> DeployResult:
    """
    1. paramiko 连接节点
    2. 把 install.sh 通过 stdin 喂给远端 bash
    3. 等命令结束，拿 stdout/stderr
    4. 从 stdout 末尾解析那行 JSON
    5. 返回结构化结果
    """
```

install.sh 内容放在 `backend/deploy/scripts/install.sh`，部署时读文件 → 通过 SSH 的 `bash -s` 方式执行，**不在节点上落盘**（脚本只用一次性，何必污染节点）：

```python
cmd = "bash -s"
stdin, stdout, stderr = ssh.exec_command(cmd)
stdin.write(install_sh_content)
stdin.write(f"\nSINGBOX_VER={version}\n# trigger\n")
stdin.channel.shutdown_write()
```

**实际写法**：用环境变量传版本号更干净：

```python
ssh.exec_command(f"SINGBOX_VER={shlex.quote(version)} bash -s", ...)
# 然后 stdin.write(install_sh_content)
```

### 错误处理

- SSH 连不上：状态变 `failed`，记错误
- bash 退出码非 0：状态 `failed`，stdout/stderr 一起塞进 deploy_log
- 末尾 JSON 解析不出：状态 `failed`，但 systemd 可能已经装好了，提示"部分成功，请查看日志"

## install.sh 完整草案（伪代码）

```bash
#!/usr/bin/env bash
set -euo pipefail

[ "$(id -u)" -eq 0 ] || { echo "需要 root"; exit 1; }

SINGBOX_VER="${SINGBOX_VER:-1.10.7}"

case "$(uname -m)" in
  x86_64)  ARCH=amd64 ;;
  aarch64) ARCH=arm64 ;;
  armv7l)  ARCH=armv7 ;;
  *) echo "unsupported arch: $(uname -m)"; exit 1 ;;
esac

mkdir -p /opt/mesh-panel /etc/sing-box
cd /tmp

TGZ="sing-box-${SINGBOX_VER}-linux-${ARCH}.tar.gz"
URL="https://github.com/SagerNet/sing-box/releases/download/v${SINGBOX_VER}/${TGZ}"

# 优先 curl，没有就 wget
if command -v curl >/dev/null; then
  curl -fsSL "$URL" -o "$TGZ"
else
  wget -q "$URL" -O "$TGZ"
fi

tar -xzf "$TGZ"
install -m 0755 "sing-box-${SINGBOX_VER}-linux-${ARCH}/sing-box" /opt/mesh-panel/sing-box
echo "$SINGBOX_VER" > /opt/mesh-panel/version
rm -rf "$TGZ" "sing-box-${SINGBOX_VER}-linux-${ARCH}"

# 占位配置
cat > /etc/sing-box/config.json <<'EOF'
{
  "log": { "level": "info", "timestamp": true },
  "inbounds": [],
  "outbounds": [{ "type": "direct", "tag": "direct" }]
}
EOF

# 校验
/opt/mesh-panel/sing-box check -c /etc/sing-box/config.json

# systemd unit
cat > /etc/systemd/system/sing-box.service <<'EOF'
[Unit]
Description=sing-box (managed by mesh-panel)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStartPre=/opt/mesh-panel/sing-box check -c /etc/sing-box/config.json
ExecStart=/opt/mesh-panel/sing-box run -c /etc/sing-box/config.json
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=3
LimitNOFILE=1048576

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now sing-box.service

# 验证
sleep 1
STATUS=$(systemctl is-active sing-box.service || true)
echo "---SOCKS-PANEL-RESULT---"
printf '{"ok":true,"version":"%s","arch":"%s","singbox_status":"%s"}\n' \
  "$SINGBOX_VER" "$ARCH" "$STATUS"
```

主控解析时找 `---SOCKS-PANEL-RESULT---` 标记后那行 JSON，前面的安装日志全留在 `deploy_log` 里。

## 不在本块做的事

- ❌ Go agent —— `socks-agent.service` 这一坨第 3 块再说，本块连 unit 都不创建
- ❌ 真实业务配置 —— 占位 JSON，第 4 块才填 SS inbound
- ❌ sing-box 升级 / 卸载 API —— 后面单独一块
- ❌ 部署进度实时流式输出 —— 同步阻塞，2 分钟超时

## 验收标准

1. 主控前端节点详情页有"部署"按钮
2. 点一下，等 30~90 秒（取决于节点下载速度），状态变"已部署"，显示 `sing-box v1.10.7`
3. SSH 到节点 `systemctl status sing-box` 看到 active (running)
4. 节点 `/opt/mesh-panel/version` 文件内容是 `1.10.7`
5. 部署日志能在前端抽屉看到全文
6. 故意把节点的 SSH 密码改错再部署，状态变"失败"，错误信息能看到
