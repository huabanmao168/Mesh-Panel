# 第 5 块：流量统计 + 一键卸载 + 路径整理

## 目标
1. **路径整理**：sing-box 配置从 `/etc/sing-box/` 挪到 `/opt/mesh-panel/`，全部自包含
2. **流量统计**：通过 clash_api UDS 拉数据，agent 上报，主控展示累计数字（不画图）

## B. 流量统计

### 数据流
```
sing-box (clash_api on UDS) → agent 每 10s 拉 → WS push → 主控入库
```

### sing-box 侧
`render_singbox_config` 自动注入：
```json
"experimental": {
  "clash_api": {
    "external_controller": "unix:///opt/mesh-panel/clash.sock"
  }
}
```
不开 TCP 端口，外网零暴露。systemd unit 加 `ExecStartPre=-/bin/rm -f /opt/mesh-panel/clash.sock` 防残留。

### agent 侧
- 新增 `traffic.go`：每 10s `GET unix:///opt/mesh-panel/clash.sock/connections`（HTTP-over-UDS，Go 用 `net.Dial("unix", ...)` + 自定义 `http.Transport`）
- 拿 `downloadTotal` / `uploadTotal` / `connections` 数组长度
- WS 上报：`{type:"traffic", up_total, down_total, conns}`
- 累计值传上来（不算差值，主控算）

### 主控侧
- 新表 `traffic_samples`：
  ```
  id / node_id / ts / up_delta / down_delta / conns_snapshot
  ```
  入库时跟上一次累计值算 delta，跨重启或 delta<0（sing-box 重启清零）按 0 算
- `nodes` 表加 `traffic_total_up` / `traffic_total_down`（BIGINT，累加 delta，永不清零）
- `nodes` 表加 `traffic_last_up_total` / `traffic_last_down_total`（临时存上次拉到的累计值，算 delta 用）
- WS handler 收 `traffic` 消息 → 算 delta → 写 sample + 更新 nodes 累计
- **清理任务**：lifespan 启动一个 loop，每小时跑一次 `DELETE FROM traffic_samples WHERE ts < now - 7 days`

### API
- `GET /api/nodes/{id}/traffic`：返回 `{total_up, total_down, today_up, today_down, conns}`
  - today_* = SUM(delta) WHERE ts >= today_start
- 节点列表的 `GET /api/nodes` 也带上 `total_up` / `total_down` / `conns`（人类可读字节由前端转）

### 前端
- `NodeList.vue`：加两列「↑总上行 / ↓总下行」（formatBytes 转 KB/MB/GB）
- 节点详情抽屉：加「流量」区块，三个数字：今日↑/今日↓/活跃连接
- 5s poll 顺手刷新

### 弊端记录
- clash_api 在 sing-box 文档标 deprecated 风险，若某天移除：备选 v2ray_api（gRPC，也支持 UDS）或 `/proc/<pid>/net/dev`（拿不到分协议数据但能看总量）
- agent 必须和 sing-box 同机（现在就是）
- socket 文件残留：unit ExecStartPre 加 rm
- 调试 curl 要 `--unix-socket`，写在 README

## C. 一键卸载

### 后端
- 新文件 `backend/deploy/uninstaller.py`：
  - SSH 连进去执行 UNINSTALL_SH（脚本内嵌字符串，stdin 喂 `bash -s`，不落盘）
  - 脚本内容：
    ```bash
    systemctl stop --no-block sing-box socks-agent 2>/dev/null || true
    systemctl disable sing-box socks-agent 2>/dev/null || true
    rm -f /etc/systemd/system/sing-box.service
    rm -f /etc/systemd/system/socks-agent.service
    systemctl daemon-reload
    rm -rf /opt/mesh-panel /etc/sing-box /etc/mesh-panel
    echo "---SOCKS-PANEL-RESULT--- {\"ok\":true}"
    ```
  - 解析 RESULT 行返回主控
- 新端点 `POST /api/nodes/{id}/uninstall`：
  - body `{delete_node: bool, force: bool}`
  - 流程：SSH 连接 → 跑脚本 → 解析结果
  - `delete_node=true`：成功后从 DB 删节点
  - `delete_node=false`：保留记录，重置 deploy_status/agent_status 为初始
  - `force=true`：SSH 不通时跳过远端清理，直接处理 DB（仅 `delete_node=true` 有意义，否则空操作）
  - 同时把这个节点的 WS 连接踢掉（如果还连着）

### 前端
- `NodeList.vue` 操作列加下拉菜单（Element Plus `<el-dropdown>`），里面放：「测试连接」「部署/重新部署」「SS 配置」「卸载」（红色文字）
  - 原本几个按钮挪进去，列表更干净
- 点「卸载」→ `ElMessageBox` 弹窗：
  - 红色警告文案「将停止并删除节点上的 sing-box / socks-agent 和所有配置」
  - 复选框「同时从面板删除此节点」（默认不勾）
  - 失败时再弹「SSH 不通？强制从面板删除（不清理远端）」二次确认
- loading 状态 + 成功 toast + 列表自动刷新

### 边界
- 卸载完节点不在 DB（delete_node=true）：列表少一行，OK
- 卸载完节点在 DB（delete_node=false）：状态显示「已卸载」，可重新部署
  - 实现：deploy_status 重置为 `pending`，agent_status `offline`，ss_apply_status `pending`，agent_token 不动（重部署时复用）

## 执行顺序

1. **路径整理** scripts.py + config_push.py + 老节点迁移段
2. **卸载** uninstaller.py + API + 前端下拉菜单 + 弹窗
3. **流量 - agent**：traffic.go + UDS HTTP client
4. **流量 - 主控**：clash_api 注入 + WS handler + 表 + 清理 loop + API
5. **流量 - 前端**：列表两列 + 详情三数字 + formatBytes
6. **重启后端/前端，用户验收**：先点部署（验证迁移） → 看流量数字跑起来 → 卸载一次重装一次

每步停一下等你确认。

## 风险与回滚
- 路径迁移失败：旧路径还在，rollback 时 install.sh 加 `--keep-legacy` 不删旧目录（暂不做）
- 卸载误点：二次确认 + 默认不勾「删除节点记录」
- 流量数据漂移：sing-box 重启累计清零，delta 算负数时按 0 处理（已说明）
- DB 字段加多了：用 SQLAlchemy `create_all` 自动建（dev 期没问题），后续上 alembic 再补迁移
